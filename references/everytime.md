# `--everytime`: 에타 기출 ↔ 설명 HTML 연결

에브리타임(에타) 강의평·시험정보 게시판에 올라온 기출 후기를 설명 HTML의 해당 부분과 연결한다. 학생이 HTML을 읽다가 "여기는 실제로 시험에 나왔던 곳"이라는 걸 바로 알게 하려는 것이다. pdf2md 스킬의 `--everytime`과 같은 규칙이고, 표시 방법만 HTML에 맞춘다. 문제 번호(Qn)도 pdf2md와 같은 기준을 쓴다. 그래야 md 노트와 HTML을 오가며 봐도 번호가 같다.

## 1. 파일 찾기

현재 작업 디렉토리와 PDF가 있는 디렉토리(보통 같은 곳), 그리고 그 하위 폴더 한 단계에서 다음을 찾는다.
- 파일명에 `에타`, `에브리타임`, `everytime`, 또는 단어로 쓰인 `eta`(대소문자 무시)가 들어간 것. `beta`처럼 단어 일부인 경우는 제외한다.
- 확장자: `.png`, `.jpg`, `.jpeg`, `.md`
- 제외: 스킬 산출물(`*-페이지별-설명.md`, `* - 설명.html`)

찾은 게 없으면 사용자에게 알리고, 에타 표시 없이 진행할지 묻는다.

## 2. 문제 목록 만들기

### 매핑 md가 이미 있을 때 (예: `데베-에타-강의매핑.md`)
- 그 파일이 **문제 번호의 기준**이다. 다른 챕터 HTML이나 pdf2md 노트와 번호가 같아야 학생이 헷갈리지 않는다.
- 매핑 md에 이 PDF의 페이지가 적혀 있으면 출발점으로 쓴다. 다만 슬라이드를 실제로 읽으면서 맞는지 검증한다. 더 적절한 페이지를 찾으면 HTML에 반영하고 마무리 보고에서 알려 준다.
- 매핑 md에 없는 새 캡처가 있으면 기존 마지막 번호 다음부터 이어서 번호를 매긴다.
- 매핑 md 자체는 사용자가 요청하지 않으면 고치지 않는다. 바꿀 점은 보고에서 제안만 한다.

### 이미지 캡처만 있을 때
- 이미지를 파일명 순서대로 Read 도구로 직접 보고 문제를 옮겨 적는다. 같은 게시글이 두 장에 걸쳐 캡처됐으면 하나로 합친다.
- 문제마다 Q1, Q2 ... 번호를 붙인다. "정규화 많이 나옴"처럼 형식이 불분명한 후기도 시험 범위 힌트로 쓸 만하면 번호를 붙인다.
- 별도 매핑 파일은 만들지 않는다. HTML 끝 `에타 기출 연결` 표가 번호 기준이 된다.
- 여러 챕터를 따로 만들 때 번호가 챕터마다 달라지지 않도록, 이미지 전체를 기준으로 한 번만 번호를 매기고 모든 챕터에 같은 번호를 쓴다.

## 3. HTML에 표시하기

표시는 문제의 답이나 정의가 **슬라이드에 직접 있거나**, 문제를 푸는 **핵심 근거**가 되는 곳에만 한다. 단어 하나 겹친다고 다 달면 표시가 의미를 잃는다.

1. **제목 배지**: 관련 h2/h3의 출처 태그 뒤에 붙인다.
   ```html
   <h3 id="b-2-1">2.1 Natural Join <span class="src">03B p.5–7</span> <span class="eta">📌 에타 Q4</span></h3>
   ```
   여러 문제면 `📌 에타 Q4, Q9`처럼 한 배지에 쓴다. 목차(`nav.toc`)의 해당 링크에도 `<span class="eta">📌 Q4</span>`를 붙인다.
2. **본문 연결 박스**: 근거가 되는 내용 바로 근처에 한 개 둔다.
   ```html
   <div class="box eta"><span class="box-title">📌 에타 Q4</span>
     <p>자연 조인 결과의 열 개수를 묻는 문제 → 공통 속성은 한 번만 남는다는 이 슬라이드 설명이 근거.</p></div>
   ```
   답을 슬라이드에서 그대로 찾을 수 없고 Claude가 추론한 것이면 그렇게 밝힌다("슬라이드에 답이 직접 있지는 않음, 아래 개념으로 풀이").
3. **슬라이드와 기출이 어긋날 때**: 용어나 표기가 바뀌었거나 범위가 달라졌으면 그 박스 안에 적는다. 예: "에타 기출은 ⋈를 썼지만 올해 슬라이드는 natural join을 SQL로만 다룸".
4. **머리말**: hero의 `.legend`에 `📌 에타` 항목을 남기고, 번호 기준 파일명을 적는다. 매핑 md가 없으면 "번호는 이 문서 끝 '에타 기출 연결' 기준"이라고 쓴다.
5. **끝 정리 표**: 원본 페이지 대응표 바로 앞에 `<h2 id="everytime">에타 기출 연결</h2>` 섹션을 둔다(템플릿에 형식이 있다). 목차에도 링크를 추가한다.
   - 열: `#` / 에타 문제 (요약) / 이 챕터 위치(본문 링크 + PDF 쪽) / 근거 / 정답·포인트
   - 근거: ● 슬라이드에 답이 그대로 있음, ◐ 관련 개념만 있고 추론 필요
   - 표 아래에 "이 챕터와 관련 없는 문제: Q1, Q2 ..."를 적는다. 학생이 그 문제는 다른 챕터에서 찾아야 한다는 걸 알 수 있다.
   - 첫 칸은 `<td>Q4</td>`처럼 `Q`+숫자만 쓴다. `check.py --everytime`이 본문 배지와 이 표를 대조한다.

`--everytime`이 아니면 `.eta` 배지, `.box.eta`, `#everytime` 섹션, legend의 에타 항목을 **모두 지운다**. 폴더에 에타 파일이 있어도 사용자가 원할 때만 들어가야 문서가 깔끔하다.
